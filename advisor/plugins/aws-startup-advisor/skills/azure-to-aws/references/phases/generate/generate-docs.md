````markdown
## Migration Steps

### Phase 1: Infrastructure Provisioning

1. Review and update `terraform/terraform.tfvars.example` → copy to `terraform.tfvars`
   and fill in your values.
2. Initialize Terraform:
   ```bash
   cd terraform
   terraform init
   terraform plan
   ```
````

3. Apply the infrastructure:
   ```bash
   terraform apply
   ```

### Phase 2: Data Migration

<If PostgreSQL in design:>
4. Export Azure PostgreSQL data:
   ```bash
   export AZURE_POSTGRES_HOST=<your-azure-host>
   export AWS_RDS_ENDPOINT=<terraform output rds_endpoint>
   export DB_NAME=<your-db-name>
   export DB_USER=<your-db-user>
   bash scripts/migrate-postgres.sh
   ```

<If S3 in design and include_storage_transfer_guide:>
5. Migrate Azure Blob Storage to S3:
   ```bash
   # Install AzCopy: https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10
   azcopy copy 'https://<storage-account>.blob.core.windows.net/<container>/*' \
     's3://<bucket-name>/' --recursive
   # Or use AWS CLI sync after exporting blobs locally:
   aws s3 sync ./exported-blobs/ s3://<bucket-name>/
   ```

### Phase 3: Application Cutover

6. Update application connection strings to point to AWS endpoints.
7. Deploy application containers to ECS (or EB) using your CI/CD pipeline.
8. Run smoke tests against the AWS environment.
9. Update DNS records to point to AWS load balancers.
10. Decommission Azure resources after successful verification.

## Verification

After apply, verify:

- [ ] Terraform outputs match expected values (`terraform output`)
- [ ] ECS tasks (or EB environments) show RUNNING / healthy
- [ ] RDS is accessible from compute security groups
- [ ] S3 buckets exist and are accessible
- [ ] Secrets Manager secrets are present
- [ ] CloudWatch log groups are emitting logs
